## 그리디 알고리즘이란?

**정의**: 각 단계에서 그 순간에 최선이라고 생각되는 선택(지역적 최적해, Local Optimal Solution)을 하여, 이 선택들이 모여 전체 문제에 대한 최적해(전역적 최적해, Global Optimal Solution)를 구하는 방식

> 최적해란 주어진 제약 조건 안에서 목적 함수를 최댓값 또는 최솟값으로 만드는 해를 의미합니다

### 전역적 최적해 보장의 한계

그리디 알고리즘은 **모든 경우에 전역적 최적해를 보장하지는 않는다.**

**예시 (코딩 테스트 합격)**
1. **명제**: '하루 4시간 이상 공부'라는 명제(순간의 최선 선택)를 기반으로 매일 최선을 다해 공부하면 코딩 테스트에 합격(전역적 최적해)할 것이라고 가정
2. **명제의 오류 가능성**: 만약 실제 합격 기준이 '5시간 이상 공부'라면, 4시간 공부라는 명제 자체가 틀려 전역적 최적해(합격)도 틀릴 가능성이 있음
3. **핵심**: 그리디는 명제를 바탕으로 지역적 최적해를 쌓아 답을 만들지만, **이 명제 자체가 틀리면 결과적으로 전역적 최적해도 틀릴 가능성**이 있는 알고리즘

### 그리디의 전략적 위치 ⭐

그리디 알고리즘은 문제 해결 플로우에서 **최종 병기**로 생각하는 것이 좋다.

**문제 해결 순서**:
```
무식하게 풀기(Brute Force) → DP(Dynamic Programming) → 그리디(Greedy)
```

**이유**: 그리디는 증명이 어렵고 명제가 틀릴 가능성이 높기 때문에, 먼저 다른 접근법을 고려하는 것이 안전하다.

## 그리디 알고리즘의 두 가지 조건

그리디 알고리즘이 최적해를 보장하려면 다음 두 조건을 만족해야 한다:

### 1. 최적 부분 구조 (Optimal Substructure)

**정의**: 문제를 작은 부분 문제로 나눌 수 있고, 각 부분 문제의 최적해가 모여서 전체 문제의 최적해를 이룸

**예시: 지폐 문제 (12,100원 만들기)**

가능한 지폐: 10,000원, 5,000원, 1,000원, 100원

```
단계 1: 10,000원 선택 → 2,100원 남음 (최적 선택)
단계 2: 1,000원 2개 선택 → 100원 남음 (최적 선택)
단계 3: 100원 1개 선택 → 완료 (최적 선택)

결과: 4개의 지폐로 해결 (최소 개수)
```

각 단계의 최적 선택이 모여서 전체 최적해를 만듦 ✅

### 2. 탐욕 선택 속성 (Greedy Choice Property)

**정의**: 각 단계에서의 최적 선택이 전체 문제에서도 최적해를 보장

**반례: 8,000원 지폐가 추가된 경우**

가능한 지폐: 10,000원, 8,000원, 5,000원, 1,000원, 100원

12,100원을 만들 때:

```
❌ 그리디 접근 (가장 큰 지폐부터):
10,000원 1개 → 2,100원 남음
1,000원 2개 → 100원 남음
100원 1개 → 완료
총 4개

✅ 실제 최적해:
8,000원 1개 → 4,100원 남음
1,000원 4개 → 100원 남음
100원 1개 → 완료
총 6개??? 아니 잠깐...

다시 생각해보면:
5,000원 2개 → 2,100원 남음
1,000원 2개 → 100원 남음
100원 1개 → 완료
총 5개
```

이 경우 "가장 큰 지폐부터 선택한다"는 명제가 항상 최적해를 보장하지 않음! ❌

**교훈**: 탐욕 선택 속성이 성립하지 않으면 그리디로 풀 수 없다.

## 증명 방법

그리디 알고리즘의 정당성을 증명하는 방법:

### 1. 직접 증명 (Direct Proof)

**방법**: 명제가 참이라는 가정하에 논리적으로 증명

**예시**: "짝수의 합은 짝수다"

```
증명:
- 두 짝수를 a = 2k, b = 2m이라 하자 (k, m은 정수)
- a + b = 2k + 2m = 2(k + m)
- (k + m)은 정수이므로, a + b는 짝수다 ∎
```

### 2. 간접 증명 (귀류법, Proof by Contradiction)

**방법**:
1. 명제가 거짓이라고 가정
2. 논리적 모순을 도출
3. 따라서 명제는 참

**예시**: "√2는 무리수다"

```
증명:
1. 반대로 "√2는 유리수"라고 가정
2. √2 = a/b (a, b는 서로소, b ≠ 0)
3. 양변을 제곱: 2 = a²/b²
4. 2b² = a²
5. a²은 짝수 → a는 짝수 → a = 2m
6. 2b² = (2m)² = 4m²
7. b² = 2m²
8. b²은 짝수 → b는 짝수
9. a, b 모두 짝수 → 서로소 가정에 모순!
10. 따라서 √2는 무리수다 ∎
```

### 3. 교환 논법 (Exchange Argument)

**방법**: 그리디가 아닌 다른 최적해가 있다면, 그것을 그리디 해로 바꿔도 더 나빠지지 않음을 보임

**예시**: 회의실 배정 문제
- 끝나는 시간이 빠른 회의부터 선택하는 그리디가 최적임을 증명
- 다른 최적해에서 더 늦게 끝나는 회의를 선택했다면, 그것을 더 빨리 끝나는 회의로 바꿔도 여전히 최적해이거나 더 좋음

## 구현 패턴

그리디 문제는 대부분 다음 패턴으로 풀린다:

### 패턴 1: 정렬 (Sorting)

**가장 흔한 패턴!** 대부분의 그리디 문제는 정렬로 시작한다.

```cpp
#include <bits/stdc++.h>
using namespace std;

// 예시: 회의실 배정 문제
struct Meeting {
    int start, end;
};

bool cmp(Meeting a, Meeting b) {
    if (a.end == b.end) return a.start < b.start;
    return a.end < b.end;  // 끝나는 시간이 빠른 순
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    cin >> n;

    vector<Meeting> meetings(n);
    for (int i = 0; i < n; i++) {
        cin >> meetings[i].start >> meetings[i].end;
    }

    // 핵심: 끝나는 시간 기준으로 정렬
    sort(meetings.begin(), meetings.end(), cmp);

    int count = 0;
    int last_end = 0;

    for (auto m : meetings) {
        if (m.start >= last_end) {
            count++;
            last_end = m.end;
        }
    }

    cout << count << '\n';
    return 0;
}
```

**시간 복잡도**: O(n log n) - 정렬 시간

### 패턴 2: 우선순위 큐 (Priority Queue)

**동적으로 최선의 선택을 해야 할 때** 사용

```cpp
#include <bits/stdc++.h>
using namespace std;

// 예시: 최소 회의실 개수 구하기
int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    cin >> n;

    vector<pair<int, int>> meetings(n);
    for (int i = 0; i < n; i++) {
        cin >> meetings[i].first >> meetings[i].second;  // start, end
    }

    // 시작 시간 순으로 정렬
    sort(meetings.begin(), meetings.end());

    // 끝나는 시간을 저장하는 최소 힙
    priority_queue<int, vector<int>, greater<int>> pq;

    for (auto m : meetings) {
        // 가장 빨리 끝나는 회의실보다 늦게 시작하면 재사용
        if (!pq.empty() && pq.top() <= m.first) {
            pq.pop();
        }
        pq.push(m.second);
    }

    cout << pq.size() << '\n';  // 필요한 회의실 개수
    return 0;
}
```

**시간 복잡도**: O(n log n) - 정렬 + 힙 연산

### 패턴 3: 정렬 + 우선순위 큐 조합

```cpp
#include <bits/stdc++.h>
using namespace std;

// 예시: 강의 선택 (최대 가치)
struct Lecture {
    int deadline, pay;
};

bool cmp(Lecture a, Lecture b) {
    return a.deadline > b.deadline;  // 마감일 늦은 순
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    cin >> n;

    vector<Lecture> lectures(n);
    for (int i = 0; i < n; i++) {
        cin >> lectures[i].pay >> lectures[i].deadline;
    }

    sort(lectures.begin(), lectures.end(), cmp);

    priority_queue<int> pq;  // 최대 힙
    int day = lectures[0].deadline;
    int idx = 0;
    int answer = 0;

    while (day > 0) {
        // 현재 날짜까지 할 수 있는 강의를 모두 넣음
        while (idx < n && lectures[idx].deadline >= day) {
            pq.push(lectures[idx].pay);
            idx++;
        }

        // 가장 돈을 많이 주는 강의 선택
        if (!pq.empty()) {
            answer += pq.top();
            pq.pop();
        }
        day--;
    }

    cout << answer << '\n';
    return 0;
}
```

### 패턴 4: 비트마스킹 + 그리디

**예시: BOJ 1285 동전 뒤집기**

```cpp
#include <bits/stdc++.h>
using namespace std;

int n;
char board[20][20];

int main() {
    cin >> n;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            cin >> board[i][j];
        }
    }

    int ans = 1e9;

    // 행을 뒤집는 모든 경우 시도 (2^n)
    for (int mask = 0; mask < (1 << n); mask++) {
        int cnt = 0;

        // 각 열에 대해 그리디하게 선택
        for (int j = 0; j < n; j++) {
            int tail = 0;

            for (int i = 0; i < n; i++) {
                char c = board[i][j];
                // i번째 행이 뒤집혔는지 확인
                if (mask & (1 << i)) {
                    c = (c == 'H') ? 'T' : 'H';
                }
                if (c == 'T') tail++;
            }

            // 열을 뒤집을지 말지 그리디하게 결정
            cnt += min(tail, n - tail);
        }

        ans = min(ans, cnt);
    }

    cout << ans << '\n';
    return 0;
}
```

**핵심**:
- 행은 모두 시도 (완전 탐색)
- 열은 그리디하게 선택 (각 열은 독립적으로 최적 선택 가능)
- 이것이 **탐욕 선택 속성**!

## 대표 문제 유형

### 1. 활동 선택 (Activity Selection)
- **대표 문제**: BOJ 1931 회의실 배정
- **전략**: 끝나는 시간이 빠른 순으로 정렬 후 선택
- **증명**: 교환 논법

### 2. 거스름돈 문제
- **대표 문제**: 동전 개수 최소화
- **전략**: 큰 단위부터 선택
- **주의**: 동전 단위가 특정 조건을 만족해야 함 (예: 배수 관계)

### 3. 최소 신장 트리 (MST)
- **대표 문제**: BOJ 1197 최소 스패닝 트리
- **전략**: Kruskal (간선 정렬 + Union-Find) 또는 Prim
- **증명**: 컷 속성 (Cut Property)

### 4. 허프만 코딩 (Huffman Coding)
- **전략**: 우선순위 큐로 가장 작은 두 원소 반복 합치기
- **응용**: 파일 압축, 최적 이진 트리

### 5. 구간 스케줄링
- **변형**: 회의실 개수 구하기, 겹치지 않는 최대 구간
- **전략**: 정렬 + 그리디 또는 우선순위 큐

### 6. 문자열 그리디
- **예시**: 사전순 최소/최대 문자열 만들기
- **전략**: 스택, 큐, 그리디 선택
